# Nori — 引き継ぎパッケージ

このフォルダは **Nori**（macOS と Windows のクリップボード履歴アプリ）の開発を、
別の開発者・別の AI が引き継ぐための一式です。

リポジトリ（最新はいつもこちら）: **https://github.com/hocky0301/Nori**

---

## 中身

| ファイル / フォルダ | 用途 |
|---|---|
| **`NORI_DOCS.md`** | 文書だけを 1 ファイルにまとめたもの（約 130KB）。**まずこれを読ませる。** |
| **`NORI_SOURCE.md`** | 全ソースを 1 ファイルにまとめたもの（約 1MB）。実際に手を入れさせるとき用。 |
| `repo/` | 実ファイルのツリー。そのままビルドできる状態（`.git` は含まない）。 |
| `repo/docs/HANDOFF.md` | 引き継ぎ本体。設計の約束・落とし穴・検証方法。 |
| `repo/docs/DESIGN.md` | 設計の原典。冒頭に「実装との差分表」あり。 |
| `repo/docs/REVIEW_LOG.md` | リリース前レビューで確定した 39 件の一覧と対応状況。 |

**入っていないもの**: `.git` 履歴、ビルド成果物（`DerivedData` / `bin` / `obj`）、
`_reference/`（参考にした Maccy の配布物。66MB あり、無くても作業できる）、
翻訳ファイルと画像の大半（`repo/` には実ファイルがあります）。

## AI に渡すときの最初の指示（コピペ用）

```
添付の NORI_DOCS.md は、私が開発している「Nori」というクリップボード履歴アプリの
引き継ぎ文書一式です。macOS 版（Swift/SwiftUI/SwiftData）と Windows 版（C#/.NET 10/WPF）の
2 実装があり、すでに v0.1.0 として公開済みです。

まず HANDOFF.md の章立てに沿って全体を把握してください。特に次の 2 つは
設計上の制約なので、提案する前に必ず読んでください:

- 「§4 設計上、動かしてはいけない約束」— 特に操作文法を 1 つに固定する方針
- 「§2.5 引き返せない操作」— タグ push が公開リリースを即発火する等

把握できたら、次の 3 点を教えてください:
1. このアプリの設計で、あなたが疑問に思った判断
2. §7「次にやるなら」の優先順位について、あなたの意見
3. 作業を始めるにあたって足りない情報

コードに手を入れる段階になったら NORI_SOURCE.md（または repo/）を渡します。
```

## 引き継ぎ時点の状態（2026-09-06）

- リリース **v0.1.0** 公開済み。macOS 版 3.5MB / Windows 版 74MB（.NET 同梱・インストール不要）。
- テスト: macOS **193** / Windows **179**、両方グリーン。CI は push ごとに両方走る。
- リリース前レビューで確定した欠陥 **37 件**（報告 39 件・うち 2 件重複）はすべて修正済み。
- **未検証**: Windows 版の実機での手触り（CI のスクリーンショットとロジックテストまでしか見ていない）。
- **未対応**: 署名と公証。Mac は初回に `xattr -d com.apple.quarantine`、Windows は SmartScreen 警告が出る。
